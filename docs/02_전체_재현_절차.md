# 전체 재현 절차

## 1. 원본 선별과 정답 판정

1. 중간모음터의 문서 목록을 책·단원별로 고정한다.
2. HWP/HWPX 문서와 PPT PDF 같은 다른 자료를 구분한다.
3. 정답으로 취급할 파일명 규칙을 명시한다.
4. 현재 해냄 작업 기준에서는 다음을 모두 정답으로 본다.
   - `정답`
   - `정답과 해설`
   - `예시 답안`
   - `예시답안`
   - `예시 답안 및 평가 기준`
5. 정답은 대응 문제 바로 뒤에 오도록 번호를 다시 부여한다.
6. 선택 기준에 없던 `수행 평가` 등은 임의로 추가하지 않는다.

목록과 정답 판정을 JSON으로 남긴다.

```bash
python -m hwp_manage inventory --workspace "작업폴더" --book "책 이름" --report "목록.json"
```

## 2. HWP를 HWPX로 준비

- 원본이 HWP라면 한컴오피스에서 HWPX로 별도 저장한다.
- 원본 HWP는 그대로 보존한다.
- 저장 결과의 stem이 원본과 맞는지 확인한다.
- macOS 화면 매크로는 접근성 권한, 저장창 언어, 한컴 버전에 의존하므로 이식 가능한 핵심 프로그램과 분리한다.
- Windows도 한컴 버전에 따라 COM/UI 자동화가 달라지므로 처음에는 수동 변환 1개로 형식을 확인한다.

## 3. 변형 중간모음터 구성

```text
목표2/국어 자료 변형 중간모음터/{책}/{n}단원/*.hwpx
```

- 파일명 번호가 병합 순서다.
- macOS NFD와 Windows NFC 파일명 차이는 프로그램이 NFC로 정규화한다.
- 원본과 변환 결과의 파일 수·stem 집합이 같아야 한다.

## 4. 사전 검사

```bash
python -m hwp_manage doctor --workspace "작업폴더"
python -m hwp_manage inspect "작업폴더/목표2/국어 자료 변형 중간모음터/책/1단원/파일.hwpx"
```

검사항목:

- HWPX가 ZIP으로 열리는지
- `mimetype`이 첫 항목이며 무압축인지
- `Contents/content.hpf`, `Contents/header.xml`, 섹션 XML 존재 여부
- 모든 XML 파싱 여부
- 이미지 참조 ID가 manifest와 실제 BinData로 이어지는지
- 마스터페이지 참조와 그 내부 이미지 참조가 유효한지

## 5. 단원 및 전체 병합

```bash
python -m hwp_manage pipeline --workspace "작업폴더" --book "책 이름"
```

프로그램은 다음을 순서대로 한다.

1. 단원 폴더를 번호순으로 찾는다.
2. 각 단원 HWPX를 자연 정렬한다.
3. 입력 파일마다 모든 섹션을 읽는다.
4. 문서별 스타일 ID, BinData ID, 마스터페이지 ID를 충돌하지 않게 바꾼다.
5. 이미지 ID는 XML 속성의 원래 값에서 새 값으로 한 번만 치환한다.
6. 각 섹션을 결과의 독립 `sectionN.xml`로 기록한다.
7. 병합 전후의 섹션 본문 해시, 섹션별 참조 이미지 해시, BinData 해시, 표·그림·수식 수를 비교한다.
8. 통과한 경우에만 임시 파일을 단원 최종본으로 원자 교체한다.
9. 단원 최종본들을 다시 같은 방식으로 책 전체본으로 병합한다.

## 6. PDF 병합

PDF 조각은 아래에 둔다.

```text
목표2/국어 자료 PDF 조각/{책}/{n}단원/*.pdf
```

```bash
python -m hwp_manage pipeline --workspace "작업폴더" --book "책 이름" --pdf
```

- 단원과 전체 PDF 모두 무가공 조각에서 직접 생성한다.
- 기존 하단 중앙 번호 영역을 흰색으로 가린다.
- 새 연속 번호를 한 번만 추가한다.
- 자동화 후 단원 쪽수 합과 전체 쪽수를 대조하고 표본 페이지를 렌더링해 확인한다.

## 7. 제출용 구조와 ZIP

```text
국어 자료 최종본 모음/
├── 0. 전체 파일 모음/
│   ├── 책_전체.hwpx
│   └── pdf/책_전체.pdf
├── 1. 책 작업용/_reports/
├── 2. 책 제출용/
│   ├── 1단원.hwpx
│   ├── 책_전체.hwpx
│   └── pdf/
└── 책.zip
```

ZIP에는 `2. 책 제출용` 폴더 자체가 아니라 그 안의 내용물만 들어간다. `.DS_Store`, `_work`, 보고서는 제외한다.

## 8. 최종 검사

```bash
python -m hwp_manage verify --workspace "작업폴더" --book "책 이름"
```

- 모든 제출용 HWPX `ok=true`
- 제출용 전체 HWPX와 `0. 전체 파일 모음` 복사본 SHA-256 동일
- PDF가 있으면 PDF 복사본 SHA-256 동일
- ZIP CRC 오류 없음
- ZIP 내부 경로·파일별 SHA-256가 제출용 폴더와 동일
- 한컴에서 대표 페이지 육안 검사

## 9. Google Drive 배포

1. 로컬 최종 검증이 끝난 뒤 업로드한다.
2. 기존 Drive 파일을 갱신할 때는 가능하면 파일 ID를 유지하는 내용 교체를 사용한다.
3. 폴더 구조와 공유 권한을 바꾸지 않는다.
4. 업로드 후 다시 다운로드해 로컬과 SHA-256를 비교한다.
5. `.DS_Store`는 업로드하지 않는다.
6. 커넥터가 로그인되지 않았으면 업로드 완료로 보고하지 않고 재연결 후 다시 실행한다.
