# 플랫폼별 HWP 변환 운영

## 공통 원칙

- 원본 HWP는 수정하거나 삭제하지 않는다.
- HWPX가 필요하다는 작업 지시가 있을 때만 별도 HWPX를 만든다.
- 첫 파일 하나를 변환하고 한컴에서 열림·표·그림·쪽 구성을 확인한 뒤 대량 처리한다.
- 원본 stem과 HWPX stem, 파일 수를 대조한다.
- 병합 입력 폴더에는 검증된 HWPX만 둔다.

## 수동 변환

1. 한컴오피스 한글에서 HWP를 연다.
2. `다른 이름으로 저장`을 선택한다.
3. 형식을 `한글 표준 문서 (*.hwpx)`로 정한다.
4. 원본과 다른 출력 위치에 같은 stem으로 저장한다.
5. `python -m hwp_manage inspect "출력.hwpx"`를 실행한다.
6. 한컴에서 출력 HWPX를 다시 연다.

Windows와 macOS 모두 수동 변환이 기준 동작이다. 단축키와 저장창 모양은 한컴 버전에 따라 다를 수 있다.

## macOS 기존 화면 매크로 이력

현재 국어정리 작업공간에는 다음 매크로가 별도로 보존돼 있다.

```text
목표2/etc/hwp_to_hwpx_gui_macro.py
목표2/etc/hwpx_to_pdf_gui_macro.py
```

이 매크로는 `/Applications/Hancom Office HWP.app`, 번들 ID `com.hancom.office.hwp12.mac.general`, AppleScript와 손쉬운 사용 권한을 전제로 한다. 공개 GitHub 핵심 패키지에는 특정 사용자 절대경로와 GUI 환경 의존성이 큰 매크로를 포함하지 않았다.

기존 작업에서 안정적이었던 운영값은 다음과 같다.

- 한 번에 한 단원만 처리
- 한컴을 실행하기 전에 복구 대화상자 처리
- 8개 문서마다 앱 재시작
- GUI 재시도 3회
- 저장창에서 긴 파일명은 짧은 임시 stem으로 저장한 뒤 원래 이름으로 이동
- 결과 HWPX 검사 통과 후 다음 문서 진행
- 원본 폴더에 중간 HWPX가 남지 않았는지 확인

매크로를 실제 실행하기 전 다른 한컴 문서를 모두 저장하고 닫아야 한다. 앱 재시작 옵션이 사용자의 다른 문서를 닫을 수 있기 때문이다.

## Windows 자동화 확장 기준

Windows 한컴 자동화는 설치 버전별 COM ProgID와 보안 모듈 정책을 확인한 뒤 별도 어댑터로 구현한다. 구현 전 확인할 항목은 다음과 같다.

- 한컴오피스 설치 여부와 버전
- Python 비트수와 한컴 비트수
- COM 객체 생성 가능 여부
- 파일 열기·다른 이름 저장 API의 HWPX 형식 코드
- 보안 승인 모듈과 팝업
- 비대화식 실행에서 문서가 실제로 닫히는지

자동화가 확인되지 않은 PC에서는 수동 변환을 사용한다. 변환이 되지 않았는데 완료로 기록하지 않는다.
